# Аудит архитектуры — 12 сентября 2026, актуализирован 19 сентября 2026

## Границы репозиториев

| Репозиторий | Ответственность | Доставка |
| --- | --- | --- |
| EasyEDA Copilot | Расширение, UI, MCP, взаимодействие с редактором | `.eext` и `easyeda-copilot-mcp` |
| EDA Copilot Backend | Поиск компонентов, схема, размещение PCB, workers и Rust solver | `eda-copilot-backend@0.2.0` |
| EDA Copilot Router | Трассировка, KRT, WASM и управление внешним runtime | `eda-copilot-router@0.3.2` |

MCP вызывает библиотеки в своём процессе, а тяжёлые вычисления backend выполняются в workers. Отдельный репозиторий backend не означает отдельный HTTP-сервис. Пакеты самостоятельно объявляют runtime-зависимости; MCP не включает backend в свой архив и не дублирует его зависимости. Пути к native/assets вычисляются относительно установленного пакета.

Backend не зависит от `@copilot/shared`. Файлы `component`, `circuit`, `lcsc`, `reused` скопированы из `copilot-server/src/types` и теперь поддерживаются в backend самостоятельно. Автоматической синхронизации с сервером нет: изменение контрактов требует явного согласования и обновления версии пакета. Внутренний `shared` EasyEDA Copilot остаётся для UI/расширения/MCP.

Backend пригоден для подключения к другим host-приложениям, но его каталог компонентов и часть форматов по-прежнему связаны с EasyEDA. Это переиспользуемая библиотека с EasyEDA-провайдером. Legacy UI и отдельный Copilot Server не переведены на эту библиотеку в рамках переноса.

## Разработка и поставка

Основной манифест использует точные npm-версии backend `0.2.0` и router `0.3.2`, поэтому обычный checkout не требует соседних репозиториев. `deps:local` включает соседние `file:`-зависимости, `deps:release` возвращает опубликованные версии. Полный порядок описан в [local-development.md](local-development.md).

Backend `0.2.0` и router `0.3.2` опубликованы по `v*`-тегам после CI через npm Trusted Publisher, OIDC и provenance.

CI EasyEDA Copilot проверяет интеграцию и установку отдельного MCP-архива с внешними npm-пакетами на четырёх платформах и Node 20/24. Публикация MCP получает проверенный архив только после всех jobs. Скрипт публикации отвергает уже занятый номер с другими байтами. Root/MCP/extension/server.json/runtime версии согласованно подготовлены для выпуска `1.2.0`; предыдущий номер `1.1.9` уже занят в npm. `check:release` проверяет структуру и согласованность, но не резервирует и не проверяет доступность номера в npm.

## Поддержка систем и доказательства

| Платформа | Backend | Полная новая интеграция MCP |
| --- | --- | --- |
| Windows x64 | CI Node 20/24; установка опубликованного пакета проверена локально | CI Node 20/24 пройден |
| Linux x64, glibc >=2.35 | CI Ubuntu 22.04, Node 20/24 | CI Ubuntu 22.04, Node 20/24 пройден |
| macOS x64 | CI macOS 15 Intel, Node 20/24 | CI macOS 15 Intel, Node 20/24 пройден |
| macOS arm64 | CI macOS 15, Node 20/24 | CI macOS 15 arm64, Node 20/24 пройден |

Backend: [все восемь jobs успешны](https://github.com/biosshot/eda-copilot-backend/actions/runs/35464344348), включая Rust-сборку, 201 тест и установку архива вне исходников. Опубликованный универсальный архив содержит четыре `.node`-библиотеки. Rust/Cargo и C/C++ toolchain конечному пользователю на этих платформах не нужны.

Локально с опубликованными backend/router прошли полный MCP check, отдельная установка MCP-архива и протокольная интеграция, тест переключения зависимостей, `check:release`, сборка расширения. Локальный Node: 26.5.0. CI проверяет Node 20/24; минимальные patch-версии отдельно не тестируются. Для MCP заявлен Node >=20.19; сборка расширения с Vite требует Node ^20.19.0 или >=22.12.0.

Windows ARM64, Linux ARM64 и Alpine/musl не поддерживаются полной цепочкой. Старые версии Windows/macOS не подтверждены этой CI-матрицей. Router при первом использовании может скачивать KRT, переносимый Python и Python-зависимости; необходим доступ к GitHub/PyPI. Отдельный CI router проверяет KRT на Linux и WASM fallback на Windows/Linux/macOS, но не доказывает KRT на каждой платформе без установленного Python.

Протокольные проверки MCP используют имитацию EasyEDA. Они проверяют установку, API, workers, прогресс и отмену, но не заменяют ручной smoke-test в настоящем EasyEDA Desktop и проверку внешних каталогов компонентов. Перед публичным релизом расширения нужен такой smoke-test.

Новая интеграция MCP: [8 из 8 jobs успешны](https://github.com/biosshot/easyeda-copilot/actions/runs/35466012142) на коммите `5a98f77`. Проверены опубликованные backend/router, установка MCP-архива вне исходников и протокольные сценарии; релизный job пропущен, поскольку запуск не по тегу.

## Оценка

Разделение соответствует зонам ответственности и устраняет сборку Rust при установке MCP. Поставка через отдельные npm-пакеты и проверка архивов защищают от случайных зависимостей на соседние исходники. Основные оставшиеся ограничения — внешние загрузки router, согласование копий контрактов с сервером и ограниченная платформенная матрица.
