Small local models

A model running locally can drive the same workflows through an MCP-capable client. The engineering tools handle coordinate-intensive work, leaving the model to express intent and review the results.

What the model needs to do

Read structured project and board data, follow the tool workflow, translate requirements into a placement or routing program, and respond to preview or DRC findings. The placement engine evaluates geometry and pin proximity. The router computes tracks and vias under the supplied design rules.

Tool-call reliability, context size and adherence to engineering constraints matter when choosing a model. A local model still needs a client that exposes the MCP tools or can run the standalone skill.

Record a reproducible run

Test the same project snapshot and task across configurations so you can see which part of the workflow changes. Published project demos document the workflow and resulting boards. Specific model configurations need their own recorded runs.

  • Model and runtime

    Model name, quantization, inference runtime, client, context limit and hardware.

  • Inputs and intervention

    Project revision, task prompt, Copilot version, tool retries and manual changes.

  • Engineering results

    Unrouted connections, native DRC findings and the saved project. Include elapsed time if comparing runs.
