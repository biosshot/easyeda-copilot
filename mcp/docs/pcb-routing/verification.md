# Routing and copper verification

Verify the requested scope after each applied transaction, using the [routing strategy](instructions.md#plan-globally-route-in-manageable-transactions) chosen for this board. The critical/GND/ordinary sequence is a recommendation; evaluate the resulting design against current capacity, coupling, impedance, length and local-loop requirements. Recheck affected critical constraints after later edits regardless of the sequence used. Before declaring a whole board complete, include every remaining group and the final ground fill.

1. **Read the result.** Review `routing`, `copper`, `diagnostics` and `drc`. A `complete` routing status describes the selected nets; a useful `partial` result is already applied. Inspect selected fields in the artifacts when the compact result omits a failing net or cause; see [operation results](../operations.md).
2. **Check connectivity through native DRC.** Use `inspect_net` for reported or critical nets and read `drc.violations`, including connection errors. It returns one summary per net: total line/arc length, track width range, segment count, via count, layers, pad membership and polygon outlines. These statistics do not determine connectivity. An unrouted net still returns DRC; without tracks, `width` is `null`. `drc.violation_count` is counted before limiting details; when `drc.truncated` is true, increase `drc_limit` (up to 200) or read the full native report through [execute_js](../execution/instructions.md). Separate deliberately deferred connections from failures in this transaction. For full-board completion, verify whole-board connectivity, including ground and any removed connections that needed rebuilding.
3. **Inspect the actual copper.** Use a layer-specific `preview_pcb` for repaired areas, package escapes and critical paths. Check pad/via geometry, widths, avoidable detours and preservation of useful existing copper.
4. **Verify differential pairs.** Check coupled routing along the same corridor, intended spacing, skew, short uncoupled escapes and suitable return paths through layer transitions. Trace every pair segment through series components. Equal lengths or no airwires do not establish adjacency. A failed coupling audit remains a finding even when both nets are connected.
5. **Verify ground fill.** Inspect the filled copper on the chosen layers: required pads and islands must connect, and critical signals need a usable reference. Check slots, narrow necks and the space around via fields. Connect a useful isolated island or remove an unused one. Ground vias should join useful copper across layers and provide needed local return connections. Auxiliary minimum-width tracks preserve a possible path; they do not prove adequate plane width, current capacity or low return-path impedance.
6. **Use current native DRC.** Reuse the router's native check if the board has not changed and the result is complete enough. Call `check_pcb_drc` for missing violation details or after later edits, refill or repair. Separate pre-existing findings from changes introduced by this work.

`preview_pcb` requires EasyEDA 3+ and returns `image_path` and `notes`. It first tries the official canvas image API, with a 10-second bridge timeout. Native previews use highlight color-map keys to select nets/components and ignore individual color values. Layer visibility and selection are restored afterward when the editor responds; the editor remains zoomed to the requested area.

On a native error or timeout, `preview_pcb` uses the legacy renderer with the same input, including custom colors. A layer-specific request also falls back when EasyEDA cannot report its active PCB layer. Read `notes` for the fallback reason: this image is reconstructed from exported primitives and may differ from the actual filled copper. Do not use a fallback image as proof of filled-plane continuity.

Zone outlines and routing counts are insufficient evidence of filled-plane continuity. If `copper.pours_pending` is nonzero or copper is missing/stale, establish that the pour has been rebuilt before accepting it. A successful native preview shows the current rendered fill; taking an image does not rebuild it.

For each blocking finding, use the [routing repair procedure](instructions.md#when-routing-does-not-converge): diagnose the location, try a justified scoped repair, or reconsider placement when geometry is the cause. After changing a keepout or obstructing copper, rebuild affected pours and recheck connections. Net-wide `clearRouting` of vias also removes ordinary vias; account for every connection that must be restored.

Keep a verified useful result, repair a local defect, or use [recovery](../recovery.md) for a clearly invalid result that cannot be repaired safely. A warning alone does not require rollback. Report the selected scope, DRC/connectivity evidence, ground and pair findings, unresolved nets, and any provisional physical assumptions. DRC success alone does not verify impedance, current capacity or signal integrity.
